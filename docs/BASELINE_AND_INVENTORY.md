# DevOpsHub — Comprehensive Baseline Report & Feature Inventory

## 1. Baseline Technical Report

| Area | Current Implementation | Evidence | Defect / Gap | Required Outcome |
|---|---|---|---|---|
| **Git Integration** | URL string stored in DB only | `ProjectService.java:48`, `Project.java:10`, no Git service class exists | No real Git clone, checkout, fetch, or branch inspection. Projects with GitHub URLs cannot execute real pipelines. | Implement `GitService` executing real Git CLI operations (`clone`, `fetch`, `checkout`, `status`, `diff`, commit SHA extraction), redacting tokens. |
| **Local Project Import** | File dialog captures folder path and saves DB record | `ProjectsView.java:465-474` calls `projectService.createProject` with hardcoded `"Java"` | No inspection of project files, no build system detection (Maven, Gradle, npm, Python), no archive extraction, no Zip Slip protection. | Implement `ProjectImportService` with automated build system detection, archive extraction safety, and project-tailored pipeline generation. |
| **Execution Working Directory** | Fixed to `./workspaces` globally | `ExecutionEngine.java:50`, `StageRunner.java:44` | Stages run in empty `./workspaces` instead of the project's source root. Real builds (`mvn compile`, etc.) fail because no `pom.xml` is present. | Resolve working directory from project's local path or cloned workspace so stage processes execute in the actual project directory. |
| **Pipeline Stage Commands** | Default commands use `echo` | `PipelineService.java:122-142`, `Stage.java:37`, `V2__sample_seed_data.sql:26-31` | `echo` commands pretend real checkout, build, test, and deploy occurred, violating Rule 1. | Provide real executable commands (`mvn test`, real git checkout, real packaging, real artifact deployment). |
| **Deployment Execution** | Not implemented (simulated by `echo`) | `StageType.DEPLOY` exists, but executes `echo "Deploying..."` | No real artifact verification, no target directory deployment, no post-deployment verification. | Implement real `DeploymentService` supporting local directory / container targets, verifying artifact arrival and checksum. |
| **Kanban Placeholder Cards** | Injects fake cards when 0 runs exist | `ExecutionHistoryView.java:416-439` `createDummyCard()` renders "Story 1", "Layout", "Code", "Tech As" | Misleads user with fake executions in empty columns. | Remove fake dummy cards; display honest empty state per column. |
| **Alerts Sidebar Placeholders** | Injects 5 fake user alerts | `AlertsSidebarView.java:68-75` injects "Nick Jonson", "Mike Peterson", etc. | Misleads user with fabricated activity when execution history is empty. | Display honest empty state ("No recent alerts. Run a pipeline to see live activity."). |
| **Dashboard Team Metric Cards** | Hardcoded text strings | `DashboardView.java:135-137` ("14 hours", "5 runners", "117 runs") | Cards never update from database and present fake metrics. | Calculate metrics dynamically from `stage_executions` table by stage type. |
| **Analytics Chart Fallback** | Injects fake failure incident | `AnalyticsView.java:192` (`series.getData().add(new Data<>("ASSERTION_FAILURE", 1))`) | Presents fake failure data when no failures exist. | Show real data only; display clean empty state when no failures exist. |
| **Analytics Date Filter** | UI dropdown exists but is ignored | `AnalyticsView.java:167-168` calls `getMetrics()` without time range | User filter has no effect on database query. | Implement time-windowed queries in `ExecutionRepository` and `DashboardService` for 7d, 30d, and Lifetime. |
| **Startup Migrations & Seed Data** | Applies seed data every restart | `DatabaseManager.java:114-119` executes V1, V2, V3 unconditionally | Re-applies seed data on every startup, overwriting user changes and violating persistence. | Implement migration tracking table `schema_version`; apply seed data only on first database initialization. |
| **Interrupted Run Reconciliation** | Interrupted runs remain in `RUNNING` | `ExecutionRepository.java` has no startup reconciliation query | Crashed or abruptly terminated processes show as indefinitely RUNNING on next startup. | Reconcile orphan `RUNNING` / `QUEUED` executions to `FAILED` with crash explanation on application boot. |
| **Secret Redaction** | Plaintext logging | `LogCollector.java:46-58`, `ProcessExecutor.java:46` | Tokens, passwords, and authenticated URLs are exposed in stdout/stderr and DB. | Implement `SecretMasker` redacting credentials before logging and persistence. |
| **Scheduler & Webhooks** | Trigger types exist in enum, but no trigger listeners | `TriggerType.java`, `ExecutionHistoryView.java:93` | No background cron/interval runner, no HTTP listener for webhooks. | Implement real `PipelineSchedulerService` and embedded `WebhookServerService` with token authorization. |
